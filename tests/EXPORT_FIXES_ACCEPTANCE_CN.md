# Brotli 导出与采样告警关联修复

2026-11-26。仅修改源码并离线验证；没有部署生产，没有真实账号调用，没有修改 Go 发送器、请求头策略或客户正文。管理页候选标识 accounts-ui17。

## 修复

- Brotli 解压使用现有 Ubuntu 镜像的 libbrotlidec，不依赖缺失的 Python brotli 包，不联网安装依赖。流式解压上限为 128 MiB；缺库、无效、截断、尾随数据及超过上限均明确报告导出错误，不输出原始敏感正文。
- 解压后继续沿用原有保守脱敏规则。body_export_version=2 标记新导出格式；原始加密 HTTP 记录和完整性标记不改变。
- 采集器升级后仅对既有采样选择范围内、以前未能解码的导出进行一次迁移。原窗口、排除清单和原始数据不变；未找到原归档时保留待处理状态，不伪造成功。
- 每个已导出样本按样本编号记录 HTTP 完整性、执行器回传和解压状态；当前请求与历史样本分别展示。一次用量刷新对应多个 HTTP 交换，必须全部核验后才能显示当前请求完整。
- 旧版 capture_issue 没有请求编号，不能可靠追溯。保留为“旧版未关联告警”，放进历史详情，不强行归给最近一次请求，也不删除历史记录。
- 最近 32 条可关联异常展示在历史区，完整脱敏样本仍在磁盘；不同环境或不同请求的监控结果不能串用。历史请求头告警标明关联编号，不再自动使新请求呈异常色。

## 发布边界

本次推送源码，不更新生产服务、容器或采样进程。未来发布需要将更新后的导出模块装入账号镜像，并同步控制端、采集器和管理页；仅更新页面不能修复旧镜像中的导出器。原 Go 执行器和请求策略无需为本次修复改动。
