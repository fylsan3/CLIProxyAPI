# UI15 菜单修复与验收

2026-11-26，Asia/Tokyo。本次只修管理界面，不升级候选执行器，不发布 audit3 采样运行时，不操作现有订阅账号和 NewAPI。

## 已复现并修复

| 问题 | 原因 | 修复 |
| --- | --- | --- |
| 路由、配置等页面顶部残留上一页内容 | Shadow DOM 的 `:host{display:block}` 使宿主 hidden 属性不能可靠隐藏，路由切换还保留旧视图 | 宿主显式遵守 hidden；切换立即清空旧视图并取消旧请求 |
| 快速切换后整页 Unexpected Application Error | 对原版动画页面使用 display:none，原版动画库在 commitStyles 时发现目标没有渲染 | 原版内容保留布局盒但不可见、不可交互；不修改原版动画库或吞掉异常 |
| 从配置跳往账号页绕开原版历史与阻止离开逻辑 | 自行 pushState(null) 并伪造 popstate，丢失原版路由索引 | 使用已固定资源内的原生 router.navigate；导航确认提交后才同步外层 accounts/management 路径，保留原版未保存提示 |
| 多个页面同时出现两个主标题、大块补充内容抢占原版区域 | 统一容器面板被插在原版页面之前 | 日志、配置、系统参数、提供商的补充信息移到下方折叠区；路由保持原版操作界面 |
| 账号页有额度而配额页不显示 | 配额页只读模型返回的历史头，没有复用主动查询结果 | 两页使用同一份 quota_view 展示函数；保留新旧观测优先规则，重置卡只在有剩余时展示，不新增上游查询 |
| 状态读取失败后缺少恢复入口 | 仅部分已知运行状态才显示错误，没有重试按钮 | 清除旧状态、显示错误与重试；401/403 回到登录，不伪装成空账号或零额度 |
| 定向账号链接、轮询焦点与折叠状态不稳定 | 只观察 accounts/management 布尔切换，未观察账号查询参数；重新渲染丢失交互状态 | 跟踪账号查询参数；保留补充区展开状态及控制焦点，输入/筛选中不替换控件 |
| 模型页文案仍称其他协议未接入 | 旧说明和后续开发状态不一致 | 改为准确说明：列表是本地模型注册清单，不能当作账号权益实测 |

## 集中检查

使用 127.0.0.1:18329 的纯本地虚构 A/B 页面；没有转发请求到生产服务或真实模型。确认以下项目：

- 九个菜单：仪表盘、AI 提供商、账号管理、路由编排、配额管理、日志查看、配置面板、系统参数、模型信息可到达。
- 快速连续切换九个菜单、模型页与原版路由切换，无残留容器面板、无新的动画崩溃。
- 配置修改但不保存，点击账号管理出现原版未保存确认；取消留在配置页，确认后进入账号页。没有保存测试配置。
- 仪表盘→指定 B 账号、前进/后退，账号过滤仍为 B。
- 账号详情原位展开/关闭、添加表单展开/收起、邮箱搜索空结果、刷新用量确认取消；取消没有发送账号查询。
- 日志补充区展开并筛选 B，只显示 B 的虚构请求记录。
- 模拟账号状态接口 503，旧数据不再显示，有重试入口；原版路由仍能打开；接口恢复后配额恢复。
- 配额页与账号页同为 A/B 的 5 小时剩余 83%、7 天剩余 58%，包含正确的历史观测提示。
- 退出登录只显示登录页，旧账号视图不再露出；浅色/暗色检查完成。
- 最终独立浏览器会话没有 error/warn；之前复现的 commitStyles 异常及自建历史的 blocker 警告作为修复前证据保留，不算最终版本错误。
- `node --check ui/compiled.js` 通过；已有 quota_windows_test.js 相关计算用例通过；界面静态检测无新增结果。

## 本机发布

使用 deploy_ui_only.py 发布，事务备份位于本机 CPAContainer/transactions/ui15-*。只更新以下五个文件和发布清单对应摘要：

- build_page.py
- ui/integration.js
- ui/linked.js
- ui/compiled.js
- static/management.local.html

验证中央 PID 不变，中央 Mac/Linux 二进制、worker、镜像描述、版本文件、配置文件和启动配置摘要不变；服务返回的 HTML 与本次构建完全一致。没有调用发布候选执行器的部署脚本，也没有重启服务或账号容器。具体结果保存在本地 evidence/ui15-publication.json。

发布后在本机 8317 管理页只读复核九个菜单、原版路由操作区、配额一致性和 accounts-ui15 标识。原生产标签中的旧 blocker 警告时间早于本次发布；未发现发布后的新增控制台错误。已打开的旧页面需要刷新，才会运行新脚本。

## 验收边界与后续

本轮是菜单、表单导航、数据展示和失败恢复验收，不是所有账号业务功能的全量验收。没有通过生产页面提交配置、改变账号优先级、授权、重启容器、刷新用量、使用重置卡或调用模型。浏览器授权/验证码/回调、重置卡消费和一小时长任务仍独立待办。采样容量上限及归档管理计划继续保留，未混入本次界面修复。
